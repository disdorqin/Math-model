## 1. 伪代码与算法呈现

**出现率：16/72 篇（22%）有正式伪代码块**，其中 14 篇用编号的 Algorithm 环境，2 篇只有 Input/Output 步骤块（2022-B-2202748、2023-D-2300229）。其余 56 篇用文字 + 公式 + 流程图交代算法，不设伪代码。计数方法：检索 “Algorithm N” 环境标题与 Input:/Output: 块；误差来源：个别篇在正文提及算法名（如 “Dijkstra Algorithm”）不计入，已剔除。

格式共性（据实看样本）：
- 标题式：`Algorithm 1: <动词性名称>`，名称即算法用途（Time-Varying Linear Optimization / Dynamic Resulting Network…）。
- 开头两行固定：`Input:` / `Output:`（大小写两种流派都有），把输入量直接写成符号串。
- 步数：短块 10–15 行是主流（2504188 的 A*+GA 块 14 行；2200084 的时变 LP 块 10+ 行）；带行号、while/if/for 结构化缩进。
- 位置：全部在模型/求解节内部，紧跟该模型的公式之后，不进附录；正文先用一句话引出（“The specific algorithm design ideas are given in pseudocode form.”）。
- 与公式的配合：伪代码步内直接引用公式编号（如 2303967 步内写 “by Equation (7) to (11)”），伪代码是公式的执行顺序，不是替代品。
- 替代形态：不用伪代码的篇常用**算法流程图**替代（2024-B-2419984 的蚁群算法只给 Figure 11 流程图，无伪代码块）。

真实样本：
- **2022-B-2200084**：Algorithm 1 时变线性优化，input 行直接列全部符号，while 循环 + 三路 if/else 分情形，步内嵌 argmin 公式——伪代码与 LP 公式同页配合的范本。
- **2025-D-2504188**：Algorithm 1 “A* and GA”，Input/Output 写成自然语言（图、起讫点表 → 路径集），步内是白话步骤（“Use the A* algorithm to search…”），可读性优先型。
- **2023-D-2303967**：Algorithm 1/2 成对出现（目标达成/目标加入两种算子各一块），无行号、for all 遍历 + 公式编号引用，是问题3“失效算子”的现成版式。
- **2024-B-2419984**：流程图替代型（蚁群路径规划只画流程图）。

## 2. 符号说明规模

**有独立符号节/符号表的：52/72 篇（72%）**；20 篇没有（多为符号少、文中随用随定义，如 2022-B-2200084 在正文内定义；2025-C 多篇预测论文无符号表）。

计数口径与误差（重要）：自动按“符号列起始行”计数对数学字体符号（粗斜体 Unicode）系统性漏检，对描述换行行偶有重复计。以下分布为自动计数（52 篇中 43 篇计出非零值），并附人工逐行核验的 7 篇校准样本：
- 自动计数分布（n=43）：最小 1，中位 11，四分位 6–22，最大 59（高值含多表合并计数，偏高）。
- 人工核验样本（逐行数）：2425792 = 15；2510006 ≈ 20；2300229 = 10；2504188 = 8；2116496 = 7；2304962 = 6；2516219 = 5。校准后判断：**典型主符号表在 5–20 条，中位约 10 条上下**。
- 结构规律：①绝大多数是**一张总表**放在假设节后/第一节模型前（Notations 多为第 2 或 3 节）；同篇出现 ≥2 个符号表标题的有 25 篇，但多为目录+正文重复命中或主表 + 子模型小表，主表仍是一张。②多模型论文（如 2425792 四个 Task）仍用一张总表 15 条打天下，不按模型分表。③高频配套句式：表尾注 “There are some variables not listed here and will be discussed in detail in each section.”（至少 7 篇用此句式）——总表只收全局符号，局部符号到节内再定义，这是控制总表规模的关键手法。④带 Unit 列的三栏式（Symbol / Description / Unit）在物理、工程类题最常见。

**合适范围（结论）**：主符号表 8–20 条是 O 奖的舒适区；超过约 25 条的表多伴随符号滥造或多表合并。控制手法不是删符号，而是“全局符号进总表 + 局部符号节内首现定义 + 表尾注声明”。

方法：统计正文行尾编号 (n) 的最大编号作为带编号公式数的下限估计（分节编号如 (5.1) 未计入，故为下限）；图表引用密度用全文 “Figure N / Table N” 出现次数（72 篇全量）。

- 规律：编号公式中位约 16 个——编号只给后文要引用的公式，不编号的行间公式不计。模型越偏优化/物理，编号越多（2516219、2504188 均为网络优化题，与本题最接近，可作参照：约 25–40）。
- 图表交叉引用密度（72 篇全量）：Figure 引用中位 20 处（四分位 15–30，最大 51），Table 引用中位 6 处（四分位 3–10）。即每篇约 20 处“Figure X shows…”式正文引用——图不是摆设，正文平均每 1.5 页要回引图一次以上。
- 图总量（图注计数，72 篇）：中位 13 张，四分位 10–15，最大 23。

## 5. 落到我们题目（1028 城论文的微观体例定版）

- **符号预算**：主符号表控制在 **14–18 条**封顶：一张总表放第 2 节（Notation），只收全局符号（城市集 V、源集 S、距离 d_ij、弱/强失真 ε^W/ε^S、出度 outdeg、累计失真 E_i、阈值 δ、边/点成本 c^W/c^S、路径父节点 p(i)、融合权重等）。三问各自的局部符号（融合系数、扰动矩阵元、备用父节点等）在各问首节内定义，总表尾注照抄 O 奖句式：“Variables used only within a single problem are defined where they first appear.”不按三问分三张表（与 2425792 多 Task 共用一表的做法一致）。
- **伪代码用 3 处**，全放求解节内、公式之后：①问题1 失真预算标签树状图算法（Algorithm 1，带 Input/Output 与行号，步内引用失真公式编号）；②问题2 多源分配 + 融合核算（Algorithm 2，可与贪心对照的整数规划变体只在正文交代，不另设块）；③问题3 失效重构算子（Algorithm 3，照 2303967 的算子块版式：Input 为失效集，步内引用重连规则公式）。每块 ≤15 行。
